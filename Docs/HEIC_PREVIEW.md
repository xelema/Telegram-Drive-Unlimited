# Desktop HEIC/HEIF preview limits

Plain desktop HEIC/HEIF still images use a separate JPEG display rendition. Original previews, ready offline copies, external opening and downloads keep the original bytes. macOS tries `/usr/bin/sips`; fallback candidates match the existing FFmpeg resource-directory/PATH search, with a bounded runtime version check requiring FFmpeg 8.1 or newer. Upstream 8.1 added automatic CLI tiled HEIF assembly ([changelog](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n8.1/Changelog)); demuxer support in 7.0 alone is insufficient. Do not map the first video stream: that selects one tile. FFmpeg's automatic grid already uses a complex graph, so output sizing supplies the final scale instead of an incompatible simple-vf filter.

The version gate accepts an anchored numeric major/minor of at least 8.1, with an optional lowercase `n` release prefix, numeric patch and `-`/`+` vendor suffix. Controlled native pipeline journeys accept `8.1.2`, `8.1-full_build-www.gyan.dev`, `n8.1-3-g0123abcd` and `9.0`; they refuse `8.0.1`, `7.1.1-1ubuntu1`, malformed `8.1foo`, and unversioned `N-121234-g0123abcd-20260901`. Master banners without a release number are deliberately refused using the existing translated preview-recovery message; dates, revision counts and hashes are never treated as a capability/version claim. No capability-probe cache is added. Original downloads/external actions remain available. The controlled helper proves gating, process routing and retained originals, not real vendor decoding on Windows.

Renditions fit 4096×4096, contain at most 8 MiB, and never upscale. Thumbnail fallback fits 480×360 and 1 MiB and retains the existing 16 MiB source-download cap; Telegram's thumbnail takes priority. Decode inputs are regular files up to 64 MiB, rejected before rendition hashing when oversized or unauthorized, with bounded 1 MiB metadata, 64 million primary pixels and bounded item/grid counts. Malformed boxes, external data references, unsupported clean-aperture/item layouts and oversized auxiliary/tile dimensions fail closed. The original remains available. AVIF, sequence frames beyond the primary still, Android/TV, WIC and bundled/WASM decoders are outside this change. No CSP or decoder dependency changes were made.

Each rendition is keyed by file/account identity, exact original path and verified SHA-256, separate from the original cache namespace. Original and JPEG hashes are rechecked on reuse; source mutation, removal/protection changes, account changes and canceled cache epochs refuse publication. One HEIF decoder runs at a time. Cache admission, byte reservations, file/category locks and original/partial paths remain held by the worker after an awaiting caller aborts. Associations are keyed per original path so viewing an offline copy cannot overwrite the online pin relationship. Pin/unpin and Clear cache cover the original/rendition pair. Offline input requires an exact account-owned plain pack/cache record; arbitrary download paths and substituted symlinks are refused. Protected sources produce no plaintext rendition.

Helpers have a 30-second total decode/probe deadline, 20 seconds per conversion, a 2-second/8 KiB version probe, output-size checks and process-tree cleanup. Linux additionally enforces a 2 GiB address-space limit. Windows creates the helper suspended, assigns a 1 GiB committed-memory Job Object, then resumes it. This macOS 15.7.9 host rejects the proposed 2 GiB RLIMIT_AS setting during preflight; macOS therefore uses a 1 GiB sampled RSS termination threshold with 10 ms requested polling. This is a reactive threshold and can overshoot; it is not a hard memory ceiling. Missing monitoring refuses execution. OS peak RSS belongs to the observed helper, not the entire app or unrelated OS services. Windows/Linux containment remains unexecuted on actual machines.

## Synthetic host measurements

Measured through the real native process/cache pipeline on macOS 15.7.9 with sips 316 and FFmpeg 8.1.2, using a debug build and warm local storage. No other gate ran during the final measurement. Full pipeline time includes source verification, JPEG validation and publication; decoder time measures the conversion child only. Peaks below distinguish OS wait4 accounting from sampled RSS; a sampled value can miss a short-lived peak.

| Decoder | Synthetic source | Decode seconds | Pipeline seconds | OS peak MiB | Sampled peak MiB |
|---|---|---:|---:|---:|---:|
| sips | 4032×3024 | 0.3421 | 3.2753 | 19.81 | 19.04 |
| sips | 8064×6048 | 3.6679 | 6.8445 | 438.25 | 438.25 |
| ffmpeg | 4032×3024 | 0.3255 | 3.3690 | 108.59 | 108.07 |
| ffmpeg | 8064×6048 | 0.5656 | 3.2319 | 221.93 | 221.30 |

Both decoders also pass the synthetic 240×180 rotation/mirror journeys: 180×240 after 90-degree counterclockwise rotation and 240×180 after vertical reflection. Pixel comparison against the transformed reference stays below 1.46 mean absolute channel levels. Full 12MP output matches the reference pattern (mean error 0 for sips and 0.493 for FFmpeg), proving full-grid assembly rather than a stretched first tile. These are synthetic transform checks, not acceptance of real iPhone metadata or color/HDR behavior.

Normal preview download/registration still occurs first under the existing preview-cache limit; the 64 MiB decoder-input limit does not prevent that preceding original download. Recorded offline/cached sources are size/provenance checked before rendition hashing.

The first uncached rendition adds one JPEG write and small account-store records; temporary decode output is removed or promoted. It needs no additional Telegram request after the original is available. A thumbnail without Telegram's own thumbnail downloads the bounded original once. Display verification reads the complete original before and after conversion/reuse, and reads the JPEG on reuse; it does not rely on timestamps alone. The cache temporarily reserves up to 16 MiB for conversion output while counting retained original bytes separately. JPEG validation allows 128 MiB of decoder allocation, independently of the child process controls. Existing cache/file/download limits still apply.

A browser/WebView that previously decoded an original larger than 4096 pixels now sees a downscaled, lossy JPEG; original opening/download remain available for full detail. Missing or unsupported decoders show translated recovery text with original actions. Real WebViews, real iPhone 12MP/48MP files, live Telegram, installed upgrades and Windows/Linux machines remain UNRUN. Desktop HEIC cannot be viewed where neither sips nor an eligible FFmpeg works, where the image exceeds these bounds, or where its layout is unsupported. Android and TV retain their existing behavior.

Fixture provenance, mutations and SHA-256 digests live in `app/src-tauri/test-support/fixtures/heic/manifest.json`. To repeat host journeys after building the native driver, run `node scripts/measure-heic-preview.cjs /absolute/path/to/synthetic-48mp.heic`; see [TESTING.md](../TESTING.md).
